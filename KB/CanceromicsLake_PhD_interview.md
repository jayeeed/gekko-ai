# CancerOmicsLake: PhD interview preparation for a conversation with Professor Rachel L. Richesson

**Prepared:** 1 November 2026. **Purpose:** a technical study module for a prospective PhD interview and for an AI assistant answering questions about this project. **Status:** interview preparation, not a submitted paper, clinical tool, or publication approval. **Reading rule:** where this file says *observed*, it means a specified repository artifact reports the result. It does not mean an independent investigator has reproduced it. Where it says *inference*, it means an interpretation that should be defended, not a fact directly measured by the software.

> **The central research story:** Broad agreement between two analyses, agreement about the few genes at the top of a list, and exact numerical reproduction are three different properties. CancerOmicsLake built a traceable cancer data platform and then measured those properties separately. The mixed and unfavorable results are part of the story.

## 01. Project identity

### What the project is

**Observed.** CancerOmicsLake is a reproducible, open-access cancer-omics data engineering platform. The first project goal was to acquire selected TCGA and GTEx data, preserve source context, standardize it, produce queryable summaries, check quality, and expose exploratory views. The implemented stack includes Python and Polars, Parquet files, DuckDB and dbt models, orchestration, FastAPI, Streamlit, and graph exports. Three TCGA projects anchor the MVP: breast invasive carcinoma (BRCA), lung adenocarcinoma (LUAD), and colon adenocarcinoma (COAD). GTEx normal tissues are breast mammary tissue, lung, transverse colon, and sigmoid colon. These are specific choices, not a claim of pan-cancer generality. See the [PRD](../PRD.md), [architecture note](architecture.md), [project config](../configs/project_config.yml), [source tree](../src/), and [dbt models](../dbt/models/).

The later research question became sharper. If a pipeline yields a reproducible candidate-gene list, how stable is that list when we change the normal reference, expression processing, tie resolution, or numerical environment? The project ran controlled comparisons and retained failures. It did **not** establish a new superior ranking algorithm or a validated biological discovery. The most defensible current description is an **auditable engineering platform with an exploratory sensitivity case study**. That assessment follows the [research overview](research_overview.md), [focused claim audit](focused_research_claim_audit.md), and [frozen v5 review](../outputs/research/global_evidence_review_v5/review.json).

**Observed status.** The milestone tracker lists all nine engineering milestones as done. That is a project completion statement about implemented components, not a scientific publication gate. The frozen v5 review has `publication_enabled=false`, `independent_human_reproduction=false`, and failed numerical acceptance. A later four-page [interview brief](../manuscript/interview_brief_v2/README.md) presents the work for discussion while retaining those limits. The [submission readiness report](../outputs/reports/submission_readiness_report.json) is an older, dated snapshot; its human and publication blockers should not be confused with current evidence of approval. Before an interview, verify the latest worklog and report timestamps rather than assuming a status value is live. [Milestone tracker](../WORKLOGS.md); [v5 review](../outputs/research/global_evidence_review_v5/review.json).

### Claim labels for an AI assistant

- **Observed:** a result, behavior, or status directly recorded in a named artifact. Quote the artifact date and denominator when important.
- **Inference:** an explanation consistent with observations but not isolated by an experiment. For example, annotation differences *may* contribute to ranking differences.
- **Proposed:** a next study or possible contribution without completed evidence.
- **Needs personal verification:** the user's individual contribution, intentions, admissions context, or author declarations.

When answering questions, lead with the shortest defensible claim. Add a mechanism or number only when you can name the evidence. Acknowledge a real weakness before defending the useful part of the project. This discipline follows the project [claim audit](focused_research_claim_audit.md).

## 02. Interview explanations

### A 30-second version

“I built CancerOmicsLake, an open-access TCGA and GTEx data platform for three cancer cohorts. It ingests and checks source files, standardizes expression and mutation records, creates warehouse tables, and exposes exploratory API, dashboard, and graph views. I then used the platform to test how candidate-gene rankings change with reference data and processing. A striking result was that broad gene effects agreed moderately across two processing routes, while the top-50 lists barely overlapped. The work is an auditable engineering and sensitivity study. It is not a biomarker claim.” [Research overview](research_overview.md); [matched-processing v2 report](../outputs/research/matched_processing_v2/report.json).

### A two-minute version

“My original problem was practical. Public cancer data are large and valuable, but a result can lose its meaning if we lose the file source, sample identity, gene annotation, unit, or processing path. I built CancerOmicsLake to keep those details connected. It uses bronze files for source evidence, typed silver tables for consistent entities and measurements, and gold tables for expression, mutation, cohort, and graph summaries. The pipeline has open-access checks, hashes, quality reports, dbt tests, and a small API and dashboard. [Architecture](architecture.md); [source](../src/).

“The more interesting research question emerged after the platform worked. I asked whether a candidate list remained stable under choices a researcher might reasonably make. One study used TCGA tumors and two different normal references. Another kept the exact specimens fixed and compared native expression with public recount3 reprocessing. In that matched study, there were 417 TCGA tumors and 200 GTEx normals. For each primary cancer comparison, we had 55,660 complete shared genes. The signed effects had Kendall tau-b around 0.56 to 0.57. Yet the tie-aware mean top-50 Jaccard was about 0.0026 to 0.0058. In plain words, a broad tendency to agree did not mean agreement on the few genes we would discuss first. [Matched-processing report](../outputs/research/matched_processing_v2/report.json).

“I also tested a lower-quantile stability ranking idea. Corrected studies did not show a top-50 advantage over the simpler maximin baseline. Numerical replay reproduced candidate lists and heldout metrics, but some strict sensitivity values still failed the frozen tolerance. I keep those as negative results. My contribution today is a transparent platform and a careful evaluation of claim fragility in this setting. The biological meaning of any candidate needs separate validation, and independent human reproduction is still pending.” [Research findings](research_evaluation_findings.md); [v5 review](../outputs/research/global_evidence_review_v5/review.json).

### A longer technical version for follow-up

Start with the unit of analysis. A row in the expression table is a measurement for a gene and a sample. It is not one participant. The native snapshot contains 36,456,660 TCGA expression rows and 11,240,000 GTEx expression rows. Those are large measurement tables. They do not imply tens of millions of people. The local mutation snapshot has 45,588 mutation records. The selected matched-processing study has 617 exact specimen matches, which is a much smaller subset. The three primary tumor-versus-normal contrasts use 417 tumors and 150 normal specimens. The other 50 GTEx sigmoid-colon normals remain in specimen-level summaries but do not enter the COAD primary contrast. [V5 review](../outputs/research/global_evidence_review_v5/review.json); [research findings](research_evaluation_findings.md); [interview brief review](../manuscript/interview_brief_v2/reviewer_notes.md).

Then explain the effect. For each gene, the rank-biserial statistic is the difference between the chance that a tumor measurement exceeds a normal measurement and the reverse chance, with ties handled through average ranks. It ranges from -1 to 1. The study computes it **inside each processing route**. Native TPM and recount3 AUC-scaled coverage are different units, so their raw values are not subtracted or treated as interchangeable. Once each route has a unit-free effect, the study compares effect ordering, direction, and top sets. This is a comparison of analytical behavior, not a differential-expression test. [Effect implementation](../src/analytics/controlled_reference_study.py); [matched-processing methods](matched_processing_v2.md).

Finally explain the three distinct checks. Kendall tau-b asks whether many gene effects have similar ordering while accounting for ties. Direction agreement asks whether effects point the same way among genes above a defined effect threshold in both routes. Top-50 Jaccard asks whether the selected sets contain the same genes. A 200-resample case/donor bootstrap describes sensitivity to the available biological units. Separately, seeded draws among exact boundary ties describe computational ambiguity in a top-k list. None of these numbers proves which processing route is biologically correct. [Metric implementation](../src/analytics/matched_processing_v2_metrics.py); [report](../outputs/research/matched_processing_v2/report.json).

### What an AI agent should never improvise

Do not supply named “validated biomarkers” from this project. Do not say the candidate ranking method beat maximin. Do not say two processing routes are independent biological cohorts; the same specimens were matched. Do not call 36 million expression rows 36 million patients. Do not treat code tests as an external validation study. Do not assign you sole authorship of every code line. When asked for a finding outside this module, inspect the report and answer with its exact scope.

## 03. Problem and motivation

### Why a data platform was needed

TCGA and GTEx answer related but different questions and were built for different purposes. CancerOmicsLake uses selected TCGA tumor and adjacent-normal material and selected GTEx normal tissues for exploratory comparison. Each source has its own metadata, file conventions, expression units, annotation, and collection process. A common gene symbol alone is not enough to prove that two values are comparable. A valid numeric column does not prove that the specimens or workflow are right for a given question. The project therefore stores the path from source file and sample metadata through the standardized table to the displayed result. [PRD](../PRD.md); [data dictionary](data_dictionary.md); [research overview](research_overview.md).

Consider a simple failure. Suppose a table has a gene ID, a sample ID, and a positive number. The schema passes. The number could still be TPM from one workflow and coverage from another. If the dashboard combines them as if they shared a unit, it may make a polished but invalid comparison. Or two rows could represent the same specimen and gene from repeated files. Counting both changes a distribution without changing any type. Or a GTEx donor could enter development in one cancer and holdout in another. Each is a problem of *fitness for a particular analysis*, not merely file readability. The code has explicit unit, key, access, and integrity checks, while the research studies expose choices those checks cannot settle. [Silver quality checks](../src/quality/checks.py); [controlled reference protocol](controlled_reference_study.md).

### Why candidate rankings are especially sensitive

Researchers often tell a short story about the first 25 or 50 genes. A ranking compresses thousands of continuous effects into a small set. Small changes near the cutoff can swap many entries. Ties can make the boundary arbitrary. If the whole effect distribution is reasonably concordant, a reader might still assume the top names are robust. The matched-processing study shows why that assumption needs a separate test. The absolute-effect top-50 lists had very low tie-aware overlap, even while signed effect ordering and thresholded direction agreement were much stronger. That is the project's central empirical observation for the available matched specimens and chosen metrics. [Matched-processing v2](matched_processing_v2.md); [frozen report](../outputs/research/matched_processing_v2/report.json).

The consequence is practical. A researcher choosing candidates for expensive wet-lab work may spend time on genes whose priority is sensitive to an upstream processing choice. A reusable data platform should show this sensitivity before the list is presented as stable. This is an **inference about research practice**, not proof that any particular selected gene is wrong. The project does not have a biological gold standard for these real cohorts. It cannot say which route produces the correct gene list. [Focused claim audit](focused_research_claim_audit.md).

### Why reproducibility is not one pass/fail switch

There are several levels. A run may finish. Its files may match hashes. The same code may make the same list in a container. Numerical values may match within a prespecified tolerance. An independent researcher may reconstruct the analysis. Finally, a biological result may replicate in independent material. Passing one level does not pass the later ones. The v5 package reports 297 passing project tests and 65 passing silver quality checks in its frozen software verification, but numerical acceptance failed. Later worklog entries record larger test counts from later work. These counts refer to different dated snapshots; they must not be blended into one current claim. [V5 review](../outputs/research/global_evidence_review_v5/review.json); [worklog](../WORKLOGS.md).

This distinction connects the engineering to research. The platform can make data traceable and expose instability. It does not remove confounding in the original sources. A checksum can prove that a file has not changed relative to a recorded digest. It cannot prove that the file contains the biologically right specimen or that a metadata assertion was true when first written. An interview answer should articulate both the value and the boundary of each safeguard. [Engineering evidence](engineering_completion.md); [contract comparison](evidence_contracts_external_results.md).

## 04. Data and methodology

### Sources and allowed access

The primary TCGA route asks the GDC for file metadata within a configured project whitelist and an open-access filter. The downloader filters for open records again and checks downloaded file MD5 digests against the source metadata. A manifest is a plan and record of files; its length is not the number of successfully parsed expression files. The corrected metadata manifest has 3,444 entries. The public-facing repository must not contain raw downloads, credentials, or controlled-access files. [GDC client](../src/ingestion/gdc_client.py); [downloader](../src/ingestion/tcga_downloader.py); [quality checks](../src/quality/checks.py); [compliance policy](compliance.md); [research findings](research_evaluation_findings.md).

GTEx supplies normal-tissue expression for the configured tissues. Native TCGA expression and GTEx expression are parsed into separate silver tables. The loader records expression units and workflow context. A recount3 arm uses publicly released processed expression to study processing sensitivity. Some selected recount3 TCGA records point back to upstream GDC metadata marked controlled. The repository treats that as a provenance distinction: its explicit public-derived mode audits the processed public release; it does not authorize downloading the controlled upstream GDC files. Do not flatten “public processed output” and “open GDC source file” into one access category. [GTEx loader](../src/processing/expression_loaders.py); [recount3 audit](research_evaluation_findings.md); [recount3 crosswalk](../src/analytics/recount3_crosswalk.py).

Gene annotations and pathway references support mapping and summaries. The gene ID normalizer removes an Ensembl version suffix while preserving `_PAR_Y`, because the latter marks a distinct pseudoautosomal locus. For example, a versioned ID can be reduced to its base ID; a `_PAR_Y` suffix stays. This is an identifier rule, not proof that different annotation releases represent every gene identically. The matched-processing audit records divergent symbol strings between native TCGA and recount3 for some shared Ensembl IDs. [Normalizer](../src/processing/normalize_gene_ids.py); [matched-processing audit](matched_processing_v2.md).

### The units of observation

Keep five nouns separate. A **file** is a source object. A **specimen** is material from a case or donor. A **sample** is a platform record that may link to a specimen. A **biological unit** is the case or donor used for partitioning and bootstrap resampling. A **measurement row** is one gene-by-sample expression value or one mutation record in its own table. A large row count is expected when thousands of genes are measured for each sample. It is not a sample-size estimate. Inspect the [data dictionary](data_dictionary.md), [silver builder](../src/processing/build_silver_tables.py), [matched study code](../src/analytics/matched_processing.py), and [frozen inventory](../outputs/research/global_evidence_review_v5/review.json) when the word “sample” is ambiguous.

The matched-processing v1 selection used exact specimen matches. It retained 162 BRCA, 136 LUAD, and 119 COAD TCGA tumors: 417 tumors. It also retained 50 GTEx normals for each of breast, lung, transverse colon, and sigmoid colon: 200 normals. Total: 617 exact matched specimens across native and recount3 processing. The three primary tumor-versus-normal contrasts use breast for BRCA, lung for LUAD, and transverse colon for COAD, so they draw on 150 of those normals. Sigmoid colon contributes to specimen-level summaries but not the COAD primary effect contrast. The exact private manifest is intentionally not a public interview artifact. [V1 findings](research_evaluation_findings.md); [v2 cohorts](../outputs/research/matched_processing_v2/report.json); [brief review](../manuscript/interview_brief_v2/reviewer_notes.md).

### Reference comparison design

The reference study compared TCGA tumors with adjacent normal and GTEx normal references. It used rank-biserial effects, fold-change alternatives, candidate rankings, heldout comparisons, and development sensitivity settings. The corrected protocol assigns a case or GTEx donor to one partition globally across the configured cancers. This repaired a historical defect: older pilot designs had 26 GTEx donors placed in different folds across cancers. Within-cancer partitioning was separate, but a global “zero leakage” claim for those older runs would be false. The corrected design keeps old evidence visible and creates new versioned runs. Shared donors can still make cancer estimates dependent; global partitioning does not make the cohorts statistically independent. [Controlled reference study](controlled_reference_study.md); [partition implementation](../src/analytics/controlled_reference_study.py); [evaluation findings](research_evaluation_findings.md).

The project evaluated a lower-quantile bootstrap stability score against simple references, including reference maximin. Maximin rewards a gene only to the extent that its signed effect remains strong against both declared normal references. That is a clear, conservative comparator. The ranking study uses development data to choose candidates and heldout data to measure replication under its own rules. It is not a clinical prediction study. Nor is the heldout set “fresh” for any later idea developed after inspecting it. [Ranking code](../src/analytics/controlled_reference_study.py); [protocol](controlled_reference_study.md); [v5 review](../outputs/research/global_evidence_review_v5/review.json).

### Matched-processing design

The processing study holds specimen membership fixed and changes the expression processing route. Each route yields one matrix for the same selected specimens. Native expression is recorded as TPM; recount3 is AUC-scaled coverage count at a 40-million target. The code computes a within-route tumor-versus-normal rank-biserial effect for every complete shared gene. It then compares two effect vectors. This design reduces specimen-selection differences between routes, but annotation and processing still differ together. It cannot isolate which one caused any observed discordance. [Matched-processing methods](matched_processing_v2.md); [report units](../outputs/research/matched_processing_v2/report.json).

V2 was specified after v1 revealed weak top-list overlap. It reused the frozen 617-specimen manifest and corrected recount3 silver table. For each cancer, it used 55,660 complete shared genes. A second, fixed “informative” universe required positive expression in at least 20% of both tumor and normal specimens in **each** route. The resulting gene counts were 33,243 in BRCA, 31,875 in COAD, and 33,684 in LUAD. The analysis reports all-shared and informative results separately. It never silently switches denominator to make a result look stronger. [V2 protocol](matched_processing_v2.md); [metric code](../src/analytics/matched_processing_v2_metrics.py); [report](../outputs/research/matched_processing_v2/report.json).

### Resampling and uncertainty

The v2 protocol fixes a seed, 1,000 point-level tie draws, 200 biological-unit bootstrap replicates, and 100 tie draws inside each bootstrap replicate. Uniformly choosing among genes tied at the top-k boundary yields a distribution for set overlap caused by **tie resolution**. Resampling cases and donors yields a descriptive interval for sensitivity to **which observed biological units appear**. The two distributions answer different questions. Neither turns matched processing into independent biological validation. The report's bootstrap interval is conditional on the available matched specimens and analysis rules. [V2 methods](matched_processing_v2.md); [implementation](../src/analytics/matched_processing_v2.py); [metrics](../src/analytics/matched_processing_v2_metrics.py).

## 05. Architecture and implementation

### End-to-end data flow

The pipeline is a sequence of observable stages: load configuration; query source metadata; download selected files when enabled; build silver tables; build gold tables; run quality checks; then export allowed graph entities. The [orchestration flow](../src/orchestration/pipeline_flow.py) records run metadata, config hash, status, and output information. The exact stage order matters because graph and consumer views should be based on tested gold outputs. The [Makefile](../Makefile) exposes command targets for manual runs, studies, checks, and packaging. A working command in the Makefile is stronger evidence than an aspirational command in the PRD.

**Bronze** preserves downloaded source files, manifest context, and metadata. **Silver** contains typed, standardized entities and facts: projects, patients, samples, file manifest, TCGA and GTEx expression, mutations, and mutation profiles. **Gold** contains query-oriented cohort, expression, mutation, candidate, and graph summaries. The code writes Parquet outputs; dbt describes warehouse staging, silver, and gold SQL models and tests. These paths are implementation choices that make large tables easier to process and audit locally. They do not by themselves show better performance than other systems. [Silver builder](../src/processing/build_silver_tables.py); [gold builder](../src/analytics/build_gold_tables.py); [dbt project](../dbt/dbt_project.yml); [dbt models](../dbt/models/).

An example trace is: a GDC file identifier and MD5 enter the manifest; a downloaded open file is checked; an expression parser identifies its unit and sample link; the normalized gene and sample measurements enter a silver Parquet table; a gold transform produces a per-cancer summary; quality checks test access, keys, units, and relationships; an API endpoint reads a gold result. The actual metadata and file structure determine which pieces are present for a given run. A report can tell whether a stage succeeded. It cannot replace inspection of the input when biological identity is disputed. [GDC client](../src/ingestion/gdc_client.py); [expression loader](../src/processing/expression_loaders.py); [quality checks](../src/quality/checks.py); [API](../src/api/main.py).

### Parsing and harmonization details

The expression loader resolves source columns and infers TCGA expression units from the chosen column and workflow. It normalizes gene IDs and links files through metadata. It filters for open-access manifest entries when resolving TCGA expression files. The silver builder writes consistent Parquet schemas for entities and measurements. The quality layer then checks key uniqueness, nonnegative expression, mapping rate, allowed units, and manifest access, among many other conditions. A default mapping-rate threshold in the basic check is 0.98; the value is a software guardrail, not a proof that all mapped genes are biologically equivalent. [Loader](../src/processing/expression_loaders.py); [gene normalizer](../src/processing/normalize_gene_ids.py); [silver builder](../src/processing/build_silver_tables.py); [checks](../src/quality/checks.py).

One concrete correction illustrates why provenance matters. Native TCGA files contained repeated sample/gene measurements. A naive mean of duplicate values would create a number not clearly attributable to one source file or workflow. The correction selects a whole-file provenance order for same-unit, same-workflow quantifications and preserves distinctions where workflows conflict. It also fixed `_PAR_Y` handling. The corrected snapshot reports 36,456,660 TCGA expression rows, 11,240,000 GTEx expression rows, and 45,588 mutation records. Those values describe the corrected local inventory at the time of the report. [Input-correction account](controlled_reference_study.md); [research findings](research_evaluation_findings.md); [v5 review](../outputs/research/global_evidence_review_v5/review.json).

### Analytical transformations

The gold builder aggregates silver facts into cohort and gene summaries. Some output tables compare tumor and mapped normal distributions; others summarize mutation frequency, functional consequences, reference sensitivity, or candidate priority. The exploratory priority tables are a triage aid. They are not a validated diagnosis or treatment recommendation. The dbt SQL models provide a second, inspectable warehouse expression for many tables and include schema and relationship tests. When asked “where is the logic?”, point to both the Python transform and the relevant SQL model, and say which one produced the cited artifact. [Gold builder](../src/analytics/build_gold_tables.py); [gold dbt models](../dbt/models/gold/); [dbt tests](../dbt/tests/); [data dictionary](data_dictionary.md).

The controlled-reference rank-biserial implementation uses pooled average ranks and a Mann–Whitney U transformation: `effect = 2U / (n_tumor * n_normal) - 1`. Positive means tumor values tend to exceed normal values. For a toy example, if a tumor value exceeds a normal value in most cross-group pairs, the effect is positive. It is near +1 if essentially every tumor value exceeds every normal value. The statistic is less tied to absolute units than a raw expression difference. It still depends on which specimens and genes are present, how ties are handled, and which processing route supplied the values. [Implementation](../src/analytics/controlled_reference_study.py).

Top-k Jaccard is `|A ∩ B| / |A ∪ B|`. If two top-50 lists share one gene, their union has 99 genes, so Jaccard is about 0.0101. The v2 code finds the score at rank *k*, keeps all genes strictly above it, and draws the remaining slots uniformly from the tied boundary set. It also reconstructs v1's deterministic exact-ID choice. This makes the effect of a large boundary tie visible instead of hiding it in a sorting rule. Kendall tau-b handles ties when comparing signed effect orderings over many genes. Neither metric is a p-value for differential expression. [Tie and concordance code](../src/analytics/matched_processing_v2_metrics.py).

### Graph, API, and dashboard

Graph builders create nodes and edges from analytical outputs, then exporters write Neo4j and Graphify-style CSV. Local full graph tables may contain Patient or Sample nodes for linkage tests. Public exports and graph-serving paths filter to `CancerType`, `Dataset`, `Gene`, `Pathway`, and `Tissue` nodes and edges whose endpoints survive that allowlist. This is a meaningful disclosure boundary, not a statement that every aggregate relationship is biologically validated. [Graph builder](../src/graph/); [public filter](../src/graph/public_graph.py); [compliance](compliance.md); [graph schema](graph_schema.md).

The FastAPI service has routes for health, metadata, gene search, expression, mutation, research summaries, graph nodes and edges, and latest quality status. The Streamlit pages provide cohort, expression, tumor-versus-normal, mutation, graph, quality, and later research views. Both are consumers of prepared results. They help a reader inspect data and caveats; they are not independent evidence of a scientific effect. For a live demonstration, use the [API implementation](../src/api/main.py), [API spec](api_spec.md), [dashboard pages](../dashboard/pages/), and [demo check report](../outputs/reports/demo_check_report.json).

### What was actually measured

These are different experiments. A test count cannot stand in for an effect estimate. A synthetic fixture cannot stand in for a patient cohort. A matched reprocessing comparison cannot stand in for an independent biological replicate. The following numbers are *observed in named, dated artifacts*, not claims of universal performance. Rounding is for speaking, not a replacement for the archived values.

The top-50 deterministic v1 Jaccard values were 0.0204, 0, and 0.0204 for BRCA, COAD, and LUAD. V2 then measured uniform boundary-tie means of 0.0046, 0.0026, and 0.0058. Native top-50 boundaries included 488, 412, and 515 tied genes. These counts are not 488, 412, or 515 *selected* genes. They describe the ambiguous pool at the cutoff. A deterministic sort can choose one reproducible set from that pool without making the choice scientifically stable. [V2 report](../outputs/research/matched_processing_v2/report.json); [tie implementation](../src/analytics/matched_processing_v2_metrics.py).

The fixed informative-gene filter raised broad tau-b to about 0.605–0.617, but informative-gene tie-aware top-50 means remained low: 0.0063, 0.0042, and 0.0086 in the same cohort order. This is a useful stress test because excluding genes with weak detection did not make leading lists agree. It does not mean every gene in the unfiltered universe is irrelevant or that the threshold is clinically optimal. [V2 report](../outputs/research/matched_processing_v2/report.json); [v2 interpretation](matched_processing_v2.md).

The report also stores 200 case/donor bootstrap replicates for each cancer and gene universe. For example, its all-shared BRCA tau-b point estimate is 0.5592 and the descriptive paired-unit bootstrap interval is approximately 0.5523–0.5671. This interval concerns resampling the available biological units. The point tie-draw quantiles concern a different operation: choosing among exactly tied genes. When explaining uncertainty, state which operation made the interval. Do not call either one an independent biological replication interval. [V2 report](../outputs/research/matched_processing_v2/report.json); [v2 methods](matched_processing_v2.md).

### Ranking and known-truth studies

The corrected full native and paired reference studies found **no top-50 advantage** for the lower-quantile stability score over simple reference maximin in BRCA, COAD, or LUAD. This result constrains the methods claim. It does not mean that every ranking method is identical, or that maximin is biologically correct. It says the more complex score did not deliver the proposed incremental benefit under the reported evaluation. An official `RobustRankAggreg` baseline was later run. Some top-50 comparisons favored the lower-quantile score over RRA, but that cannot erase the failure against maximin. Shared tumor samples also violate a simple independent-list interpretation of RRA significance. [Reference findings](research_evaluation_findings.md); [official RRA study](published_rra_baseline.md); [v5 review](../outputs/research/global_evidence_review_v5/review.json).

The constructed truth benchmark used five scenarios with 20 independent simulated datasets each and compared eight ranking strategies. In the shared-normal-bias scenario, lower-quantile top-25 truth precision was 0.018 and maximin precision was 0.016, while reference replication was 1.000. Thus both references could agree almost perfectly on the selected list while the list missed the constructed true effects. This is a counterexample under a simulation, not an empirical estimate that 98% of real candidates are false. It demonstrates a logical limit of using agreement between dependent or jointly biased references as proof of biological truth. [Simulation report](../outputs/research/reference_truth_simulation_v1/report.json); [evaluation findings](research_evaluation_findings.md); [simulation implementation](../src/analytics/reference_truth_simulation.py).

## 07. Design decisions and alternatives

**Open-access-only acquisition.** The default GDC query and downloader restrict to open files. This makes the project easier to reproduce and safer to share. A controlled-access expansion would require authorization, governance, and a different release design. It would not be a routine scale-up. Public recount3 processed expression is tracked separately from controlled upstream GDC provenance. The alternative of treating every derived file as an open GDC file would hide a material access distinction. [GDC client](../src/ingestion/gdc_client.py); [downloader](../src/ingestion/tcga_downloader.py); [recount3 audit](research_evaluation_findings.md).

**Layered tables and explicit provenance.** Bronze keeps source context; silver makes entities and measurement types stable; gold gives consumers smaller query-oriented outputs. A single denormalized CSV would be simpler at first, but it would make repeated parsing, source checks, and correction history harder to reason about. The layered pattern is an engineering choice, not a novel lakehouse architecture. Parquet and Polars support a large local measurement table; DuckDB and dbt provide inspectable analytical SQL. Performance superiority over alternative stacks was not established. [Architecture](architecture.md); [silver builder](../src/processing/build_silver_tables.py); [gold builder](../src/analytics/build_gold_tables.py); [workflow evidence](../outputs/research/global_evidence_review_v5/evidence/workflow.json).

**Stable gene identifiers and whole-file duplicate resolution.** Ensembl identifiers provide a more stable join key than displayed symbols, but annotation versions still differ. `_PAR_Y` must remain distinct. For same-unit, same-workflow repeated quantifications, the project orders provenance and chooses a file rather than averaging repeated values into a new, untraceable value. Alternatives include averaging, taking the first row, or dropping all duplicates. Each changes the meaning of the measurement. The chosen rule makes its source accountable, although it cannot prove the chosen file is biologically best. [Normalizer](../src/processing/normalize_gene_ids.py); [correction account](controlled_reference_study.md).

**Within-route, unit-free effects.** Native TPM and recount3 coverage are not numerically interchangeable. The rank-biserial effect permits comparison of order and direction after each route is analyzed on its own scale. Direct subtraction of TPM and coverage would answer no coherent measurement question. Even a unit-free effect cannot remove specimen selection, annotation, or processing bias. The method trades absolute-scale interpretation for a more defensible cross-route diagnostic. [Effect code](../src/analytics/controlled_reference_study.py); [v2 methods](matched_processing_v2.md).

**Strong simple baselines and versioned negative results.** Reference maximin tests whether a complex lower-quantile score adds value beyond a transparent conservative rule. Official RRA adds a published comparator. The project retained the no-advantage result against maximin, then kept v1 and v2 processing studies separate. The alternative would have been to retune the score or overwrite an unfavorable report after inspecting it. That would weaken the evidence. Later exact-arithmetic, contract, and recomputation screens likewise compared against existing methods before claiming novelty. [Reference findings](research_evaluation_findings.md); [RRA baseline](published_rra_baseline.md); [focused claim audit](focused_research_claim_audit.md).

**Private intermediates and aggregate public views.** Exact specimen manifests and per-gene study intermediates remain in ignored local research paths. Public graph views exclude patient and sample nodes by default. Aggregate reports can still be informative in an interview, but they need privacy and quality review before release. This boundary limits an outside reader's ability to reconstruct the analysis from public files alone; that is one reason the independent handoff and release package are separate tasks. [Compliance](compliance.md); [public graph filter](../src/graph/public_graph.py); [independent handoff](independent_reproduction_handoff.md).

## 08. Limitations, failures, and unfinished work

**Source and disease are confounded.** A TCGA tumor versus GTEx normal contrast changes disease status and data source together. Collection, tissue handling, processing, and participant composition can differ. A strong gene effect may reflect some mixture of these factors. Adjacent normal tissue has different limitations and is not interchangeable with a healthy external donor. The project reports reference sensitivity but does not claim full batch correction or a causal tumor effect. [Batch-effect sensitivity](batch_effect_sensitivity.md); [research findings](research_evaluation_findings.md).

**Matching does not isolate a mechanism.** Native and recount3 values were compared on exact specimens, which removes one large source of membership change. The routes also differ in workflow and annotation. The v2 audit counted 20,347 differing symbol strings among shared TCGA/recount3 Ensembl IDs, while GTEx/recount3 shared symbols matched in that audit. This is an observed discrepancy. It does not prove that symbol differences caused weak top-list overlap. A causal account would require a design that changes one factor at a time, with appropriate comparable inputs. [Matched-processing audit](matched_processing_v2.md); [frozen report](../outputs/research/matched_processing_v2/report.json).

**Top-list metrics have their own failure modes.** Exact top-k Jaccard is easy to explain, but large ties make it sensitive to the cutoff rule. A tie-aware mean helps reveal that issue. A detection filter changes the eligible universe and must be declared. Kendall tau-b can remain moderately high when the few top-ranked genes change. Direction agreement was calculated only among genes meeting the stated absolute-effect threshold in both routes; it is not an all-gene rate. These qualifications are essential to interpreting the apparent contrast among metrics. [Metric code](../src/analytics/matched_processing_v2_metrics.py); [v2 report](../outputs/research/matched_processing_v2/report.json).

**Study sequence matters.** V2 was a diagnostic designed after inspecting v1. Older donor partitions were corrected after a global leakage audit. Existing inspected holdouts cannot become fresh confirmation data for a later method. Simulation has known truth only because the investigators constructed it. None of these studies supplies an independent biological cohort with ground-truth gene effects. The honest next step is a prespecified endpoint and new evidence, not stronger wording about the existing results. [Evaluation findings](research_evaluation_findings.md); [controlled reference protocol](controlled_reference_study.md); [brief review](../manuscript/interview_brief_v2/reviewer_notes.md).

**Numerical and external gaps remain.** The archived candidate lists and heldout metrics reproduced, but strict numerical tolerance failed in some sensitivity cells. The external workflow comparison did not demonstrate speed superiority. The closest prior same-specimen processing work, Arora et al., has not been directly replicated in this project because the checked published matrices were inaccessible during the audit. Independent investigator reproduction remains unverified. Publication and DOI deposit remain disabled. If asked whether the platform is “fully reproduced” or “ready to publish,” the answer is no under the current gates. [Numerical evidence](../outputs/research/global_evidence_review_v5/evidence/numerical.json); [Arora audit](arora_external_comparator_feasibility.md); [v5 review](../outputs/research/global_evidence_review_v5/review.json).
